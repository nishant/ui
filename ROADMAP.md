# Roadmap

Open work only. Delete an entry in the PR that finishes it; git history is the record.

## Ideas

- **1.0 block follow-ups from the app adoption** (2026-11-01, standards-adoption): `AppShell` gets a collapsible lg+ sidebar, a banner slot, a logged-out mode without nav and a custom header name; `NumberField` gets the spinbutton role and aria-value attributes (arrow keys already nudge) and allows negatives when `min` permits; settings blocks get a compact variant; `apiFetch` error wording matches status and workflows; `useUrlState` stops splitting comma values like "Austin, TX"; `cn()` keeps custom text sizes such as trackers' `text-body-sm`.
- **Clear the `react-hooks/refs` warnings** (2026-10-31): ui lints itself now (`npm run lint`); 36 hits of `react-hooks/refs` (refs read or written during render in flow, overlay, resource, url-state, hooks, command, nav, segmented, canvas) are set to "warn" in `eslint.config.ts` (`TODO(standards)`). Fix them by moving the latest-value refs into effects, then make the rule an error.
- **npm is the default install** (2026-11-02, do before web components): every release is already on npm as `nish-ui`, but `tools/fanout/pin.mjs` and `scripts/bump-consumers.sh` still write the codeload URL, so no app installs from npm. Make the fan-out write the alias `"@nish/ui": "npm:nish-ui@X.Y.Z"` (imports stay `@nish/ui`; still read old codeload pins so it can migrate them), and move the npm publish in `scripts/release.mjs` ahead of the fan-out so a bump never points at an unpublished version. Next release migrates every app in `hosting/fleet.yaml`. README, docs/RELEASING.md and design.nish.software lead with `npm install nish-ui`; codeload stays documented as the fallback. Repos: every app in the fleet (via the fan-out), skills (any skill that writes the codeload pin).
- **Web components so @nish/ui works everywhere** (2026-11-02, after npm default): only React apps get components today; artifacts and the non-React apps (artifacts, inbox, nish.software, nishboard, trading) get only tokens and CSS. Decided approach, additive so no app changes: React components stay exactly as they are. Static pieces (button, card) get plain CSS classes (`nui-button`) with the same look. Interactive pieces (theme toggle, dialog/sheet, toast, bottom nav) become Lit custom elements (`<nish-dialog>`) with no shadow DOM, so tokens and Tailwind apply. To prevent drift, the look moves into those shared CSS classes and the behavior (focus trap, toast queue, theme switching) into framework-free TS, both used by the React and the element versions. Ship as `nish-ui/elements`, one bundle with Lit inside that React apps never load, which artifacts get from jsdelivr at a pinned version (`cdn.jsdelivr.net/npm/nish-ui@<version>/...`). Each design.nish.software page shows React and HTML side by side with live demos, and a CI screenshot check fails when the two versions differ. Out of scope: Angular, `@lit/react` wrappers replacing React, SSR for elements. Repos: skills (`artifacts` and `trip-plan` skills load the bundle), then the non-React apps adopt it.
