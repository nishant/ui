# Roadmap

Open work only. Delete an entry in the PR that finishes it; git history is the record.

## Ideas

- **1.0 block follow-ups from the app adoption** (2026-11-01, standards-adoption): `AppShell` gets a collapsible lg+ sidebar, a banner slot, a logged-out mode without nav and a custom header name; `NumberField` gets the spinbutton role and aria-value attributes (arrow keys already nudge) and allows negatives when `min` permits; settings blocks get a compact variant; `apiFetch` error wording matches status and workflows; `useUrlState` stops splitting comma values like "Austin, TX".
- **Clear the `react-hooks/refs` warnings** (2026-10-31): ui lints itself now (`npm run lint`); 36 hits of `react-hooks/refs` (refs read or written during render in flow, overlay, resource, url-state, hooks, command, nav, segmented, canvas) are set to "warn" in `eslint.config.ts` (`TODO(standards)`). Fix them by moving the latest-value refs into effects, then make the rule an error.
- **npm is the default install** (2026-11-02, do before web components; spec: [docs/specs/nish-ui-everywhere.md](docs/specs/nish-ui-everywhere.md), Stage A): every release is already on npm as `nish-ui`, but `tools/fanout/pin.mjs` and `scripts/bump-consumers.sh` still write the codeload URL, so no app installs from npm. Make the fan-out write the alias `"@nish/ui": "npm:nish-ui@X.Y.Z"` (imports stay `@nish/ui`; still read old codeload pins so it can migrate them), and move the npm publish in `scripts/release.mjs` ahead of the fan-out so a bump never points at an unpublished version. Next release migrates every app in `hosting/fleet.yaml`. Then rewrite "Who consumes it" in docs/RELEASING.md and the alias/codeload lines in the README and on design.nish.software's Getting started (both already lead with `npm install nish-ui` since 1.4.1). Repos: every app in the fleet (via the fan-out), skills (any skill that writes the codeload pin).
- **Web components so @nish/ui works everywhere** (2026-11-02, after npm default): people outside React should be able to use the whole general-purpose library, not a sample. Additive: React components never change. Elements are Lit custom elements in light DOM over the existing `nish-*` classes and `src/theme.ts` helpers, shipped as one self-contained `nish-ui/elements` bundle (artifacts load it from jsdelivr), with an HTML tab on every docs page and a React-vs-element parity test. Wave 1 (theme toggle, sheet, dialog, toast, bottom nav; button and card stay `.nish-btn`/`.nish-card`) is fully specced in [docs/specs/nish-ui-everywhere.md](docs/specs/nish-ui-everywhere.md), Stage B; Stage C then rebuilds every artifact on artifacts.nish.software on the design system. Waves 2 (forms, combobox, tabs, segmented, list row, feedback, display) and 3 (table, filters, media, split, nav, settings blocks, command palette, charts) follow the same pattern and need their own spec. React-only plumbing (hooks, `useUrlState`, resource, error boundary) and app-specific pieces (inbox client, `AppShell`) stay React-only. Repos: skills (`artifacts`, `trip-plan`, `ui-component`), artifacts (Stage C), then the non-React apps adopt it.
